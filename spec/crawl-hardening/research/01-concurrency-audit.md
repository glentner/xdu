# Crawl concurrency audit — `src/bin/xdu.rs`

Scope: correctness of the index-build crawl (shared rayon pool + `--jobs` driver threads +
`Mutex<VecDeque>` queue + `thread::scope` join). All line numbers are `src/bin/xdu.rs` unless noted.
Release sets `panic = "abort"` (`Cargo.toml:49`); tests/debug default to `unwind` — this asymmetry is
load-bearing below. There is **no** counting/reporting of skipped entries and **no** run-level
"index complete" marker anywhere in the file (confirmed by full read).

## Findings (most severe first)

| # | Title | Class | Lines | Failure scenario (inputs → outcome) | HPC severity | Fix direction |
|---|-------|-------|-------|-------------------------------------|--------------|---------------|
| 1 | **Walk error silently drops an entire subtree** | **REAL BUG** | 355–359 | jwalk yields `Result<DirEntry,_>`; when a subdir's `read_dir` fails (EACCES / EIO / stale NFS handle), jwalk emits **one `Err` in place of all its children** and never yields that subtree. `Err(_) => continue` discards it. Input: one unreadable dir near a partition root → millions of files absent from the index, run exits **0**, index *looks* complete. | **CRITICAL** — the headline correctness failure; operators audit/delete off a silently-incomplete index. Directly violates GOAL R3 ("swallowed error") and R2 ("lost file"). | Count errors per partition; surface path+errno to stderr; fail the run non-zero when any walk error occurred (or via a documented `--allow-errors` opt-in). Contrast: top-level enum is fail-loud (`entry?` @204, `read_dir …?` @201–203) — recursive walk is not. |
| 2 | **Partial index indistinguishable from complete (no completion marker)** | **REAL BUG / design gap** | 456–457, 493–514, 519–521 | A driver `Err` (e.g. `buffer.add(record)?` @381 on ENOSPC) returns from its closure, but **other drivers run to completion** and `finalize()` their partitions to real `.parquet`. `first_error` is returned → process exits non-zero, **but** the succeeded partitions are on disk and readers glob `*/*.parquet` with no way to tell "3 of 10 partitions" from "all 10". Worse over a prior index: new+stale partitions coexist silently. | **HIGH** — exit code is seen only by the `xdu` invoker; a later `xdu-find`/`xdu-rm` sees a plausible index. Violates R3 second clause ("SHALL NOT silently finalize a partial index as if complete"). | Add a run-level success gate: write a `_SUCCESS`/manifest only after *all* drivers return `Ok`, and/or build into a temp index dir then atomically swap; readers should require the marker. A marker is warranted. |
| 3 | **`__root__` partition collision → clobber / data loss** | **REAL BUG** | 29, 220–237, 53, 76–87, 108, 130–153 | A real top-level subdir literally named `__root__` becomes a full-depth WorkItem (`partition="__root__"`, `max_depth=None`). If loose top-level files also exist, `has_root_files` (@221,231) pushes a **second** synthetic `__root__` WorkItem (`max_depth=Some(1)`). Two WorkItems → two drivers → both `PartitionBuffer`s start `chunk_counter=0` (@53) and write `000000.parquet.partial` into the **same** `outdir/__root__/`: `File::create` (@108) truncation + racing `fs::rename` (@132) → lost/torn chunks. Even **serialized** (jobs=1): the second `finalize()` prune loop (@143–153) deletes the first's chunks (`num_chunks` mismatch) and chunk ids collide. | **MEDIUM-HIGH** — requires a pathological name (not FS-reserved; an operator could have one), but corruption is silent. | Reject (clear error) or namespace-escape a real `__root__` subdir vs. the reserved partition; assert no two WorkItems share a partition name. |
| 4 | **`fs::metadata` error drops the file** | **REAL BUG (small blast)** | 365–368 | Walk yields a regular file; the re-`stat` (`fs::metadata`, @365 — note this is a *second* stat after jwalk already typed it @361, a TOCTOU window + R5 inefficiency) fails (file raced-away, EACCES) → `Err(_) => continue` drops it silently. Input: file deleted between walk and stat → absent from index, no report. | **MEDIUM** — one file per event, but unbounded aggregate and silent (same R3 class as #1). | Same as #1: count + report; distinguish ENOENT-race (benign) from EACCES/EIO (report/fail). Consider using jwalk's already-fetched metadata to avoid the second stat. |
| 5 | **Non-UTF-8 path corruption via `to_string_lossy`** | **LATENT HAZARD** | 376 (& 209) | `entry.path().to_string_lossy().to_string()` maps invalid UTF-8 bytes to U+FFFD. Schema is `Utf8` (`lib.rs::get_schema()`) so raw bytes can't be stored. Result: a mojibake/Latin-1 filename is stored corrupted → **won't round-trip**; `xdu-rm` unlinks a `…�…` path that doesn't exist → real file never deleted. Two distinct invalid names can also collapse to the same string. At line 209 the same lossy conversion on partition **names** can collapse two distinct top-level dirs into one partition → same clobber as #3. | **MEDIUM** — rare on well-run HPC, non-zero on user trees; silent. | In-scope: count+report lossy conversions (fail-loud-ish) or skip+warn. True fix needs a bytes/schema change (out of scope per no-gos — flag as follow-up). |
| 6 | **`panic="abort"` makes the join-`Err` arm dead code; weak panic diagnostic** | **LATENT HAZARD** | 495–506, `Cargo.toml:49` | In **release**, any panic (driver thread *or* rayon pool worker) aborts the whole process (SIGABRT, exit 134) before unwinding — so `handle.join()` never returns `Err`; the `"Driver thread panicked"` arm (@502–505) runs **only under `unwind` (tests/debug)**. R3 "fail loud" is technically met (abort ≠ 0) but the "clear diagnostic" is the raw panic message, and already-finalized partitions persist (see #2). Note: our per-entry code (stat/`buffer.add`) runs on the **driver** thread; pool workers run only jwalk-internal readdir/stat, so an in-our-code panic is a driver panic. | **LOW-MEDIUM** — diagnostic/robustness, not data loss. | Accept abort but rely on #2's marker for partial-index safety; add a panic hook with a clear message; treat the join-`Err` arm as test-only (comment it as such). |
| 7 | **Empty `__root__` from a symlink-only trigger** | **LATENT HAZARD (minor)** | 220–221, 231, 361 | `has_root_files` is set on `is_file() || is_symlink()` (@220), but the walk (`follow_links(false)` + `is_file()` @361) never indexes symlinks. A root with only top-level symlinks (no regular files) spawns a full `__root__` WorkItem that indexes **0 files** — a wasted driver slot/bar and a misleading "Finished __root__ (0 files)" line. (Top-level fifo/socket/dev correctly set nothing and are never indexed.) | **LOW** — cosmetic + wasteful. | Gate `has_root_files` on `is_file()` only. |
| 8 | **`finalize()` prune gap-tolerance; no fsync** | **NON-ISSUE (caveats)** | 125–156 | Rename loop (@130–139) + prune-from-`num_chunks` (@143–153) is **correct in isolation**: this run writes `000000..num_chunks-1`, prune starts at `num_chunks` and removes the contiguous stale tail of a prior larger run, `else break` @151. Gaps can't arise from normal sequential chunking; the `break`-on-first-missing only mis-handles gaps injected by #3 or external tampering. Separately, no `fsync` of files/dir before "done" → power-loss durability gap (beyond concurrency scope; per-file-not-per-partition atomicity is the documented invariant #2). | n/a | Leave; optionally harden prune to scan the dir rather than break on first gap. |
| 9 | **Atomics `Relaxed` / mutex `.unwrap()` poisoning** | **NON-ISSUE** | 282–292, 320, 384–385, 404–416, 458, 519–521 | `AtomicU64/Usize` are pure counters; `fetch_add` is atomic under any ordering and nothing dependent is published through them. Final loads (@519–521) are after `thread::scope` join → happens-before holds, values exact. Lock poisoning: the only code inside `queue.lock()` is `pop_front` (@320–322) and inside `global_speed_state.lock()` is arithmetic/`format_speed` (@406–426) — neither panics; and under abort a first panic kills the process before any second `.lock().unwrap()`. Correct today; latent only if panic-prone code migrates into a critical section. | n/a | Leave; keep critical sections panic-free. |
| 10 | **No early cancellation after first error** | **minor** | 318–508 | After a driver `Err`, remaining drivers drain the whole queue, enlarging the on-disk partial index (compounds #2) and wasting work. | LOW | Signal an `AtomicBool` cancel flag checked at loop top (@318). |
| 11 | **Per-driver serial record processing / pool oversubscription** | **NON-ISSUE (correctness) — R5 note** | 296, 355–381 | jwalk parallelizes only directory *reads* on the shared pool; the driver consumes its walker **serially** (stat + serialize on the driver thread). With `num_drivers==jobs` there are `jobs` drivers + `jobs` pool threads (~2×jobs) contending; no deadlock (no lock held across a pool submit; jwalk feeds an ordered channel). The "one huge partition can't starve the rest" claim holds for *read* balancing; single-threaded per-partition record processing is the real perf ceiling for a lopsided tree. | n/a (perf) | R5: measure; consider fewer drivers vs. pool size, or parallel record building. |

## Test ideas (drive the real `xdu` binary; assert post-conditions, not exit 0)

- **#1 lost subtree:** build a tree with `part/sub/` containing N files; `chmod 000 part/sub` (run as non-root), crawl, then assert the index row count == files outside `sub` (reproduces the silent loss) — and, post-fix, assert **non-zero exit** + a diagnostic mentioning `sub`. Restore perms in teardown.
- **#3 `__root__` collision:** create a top-level subdir literally named `__root__` with known files **plus** a loose top-level file; crawl; assert every `__root__`-subdir file is queryable via `xdu-find -u __root__` (fails today — clobbered/pruned). Also test the serialized case (`-j 1`).
- **#4 metadata race:** harder to make deterministic; approximate with a top-level file removed between two crawls, or a file with `chmod 000` + parent traversal, and assert it is present-or-absent per the chosen policy.
- **#5 non-UTF-8:** create a file whose name is invalid UTF-8 (e.g. `\xff`); crawl; assert the stored path round-trips (or, post-fix, that the lossy conversion is counted/reported) — today `xdu-rm` on that row is a no-op.
- **#2 partial index:** force a mid-run driver error (e.g. make one partition's `outdir` un-writable, or fill a small tmpfs); assert non-zero exit **and** that a completeness marker is absent / readers refuse the index (post-fix).
- **#6 panic:** only reproducible under a `unwind`/debug build or a deliberate panic injection; in release, assert the process aborts non-zero rather than printing the graceful message.
